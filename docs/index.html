    Diagnose a recording

    The same method, running in your browser on raw vibration. On the nine reference recordings it gives the Python analysis's answer to within 0.0001 dB. The NASA snapshots were picked by rule, not by result, which is why two of them come back declined.

    A vibration recording from an accelerometer fixed to the bearing housing, at least one second long, with the machine at a steady speed. CSV or text with one number per line (the first column is used if there are more), or a 16-bit or 32-bit float WAV. The file is read in this tab and never leaves it.

    A built node

    The console reads a real node over Bluetooth with the same panel. A node sends one line, for example VIGIL1|id=VIGIL-0001|phase=normal|learned=144/144|hi=2.31|part=none|outer=7.6|inner=6.0|ball=7.6. None has been built yet, so this has not been run against hardware. It needs Chrome with Bluetooth, and the passkey on the node's label.

    Once opened, the console keeps working with no connection, which is how a workshop computer would run it.

    How it was tested

    Every figure on this page, the method, the C firmware for the node, what failed first and what is not built yet: the results. The code and the analysis are open.
